# Address Detection: deterministic fuzzy chain on raw STT

Address Detection is a deterministic staged chain behind an `AddressDetector` interface. An LLM "who is being addressed?" judge or a two-stage (heuristic + LLM fallback) variant is deferred to v1.5+ and can slot in behind the same seam without touching the orchestrator.

It runs on the **raw STT final transcript** — no LLM transcript-correction step sits in front of it. This removes v1's failure mode where a correction pass rewrote NPC names ("Grimjaw" → "Grindstone") before the matcher saw them.

The chain, per utterance:

1. **Explicit name/alias match** — fuzzy (see below) against active Agents' names and aliases.
2. **Last-speaker continuation** — if no name matched and the previous addressee is still active and not Address-Only.
3. **Single active NPC fallback** — if exactly one non-Address-Only NPC is active.
4. **No target** — the utterance routes to no Agent (it is still transcribed).

`Detect` returns the matched *set* of Agents (usually one). When more than one is named, the turn-taking layer would run an Ensemble Turn (ADR-0025) — but **v1.0 ships single-target by default** (see below). Puppet/"speak-as" is **not** a chain stage: the GM voicing an NPC is the `/say <text> as:<agent>` slash command (ADR-0010), an explicit-target path that bypasses Address Detection, so v1's voice-level puppet-override stage is not carried over.

**`MaxTargets` — single-target is the default.** The matcher caps how many Agents one utterance may address via `Config.MaxTargets`, applied to the score-sorted hits **before** the published decision set is built (so only the Agents actually addressed are recorded as the next turn's continuation context). The zero value defaults to **1**: naming two NPCs in one breath fires **one** turn on the top-scored Agent, not two. This is the safe default because all NPCs share one Barge-in floor (ADR-0027, ADR-0038) — a single addressed turn keeps the floor's one-turn-at-a-time invariant intact. The full Ensemble Turn set is **opt-in**: a positive `MaxTargets > 1` caps at N, and a negative value (`-1`) lifts the cap entirely, restoring the unbounded score-sorted set ADR-0025 assumes. The Ensemble Turn remains the design-of-record and is reachable through this knob; only its speculative-lead / cross-talk turn-taking layer is deferred (ADR-0025, ADR-0038).

**Butler addressability.** Agents carry an `AddressOnly` capability: reachable only via stage 1, excluded from last-speaker and single-NPC fallback. The Butler defaults `AddressOnly=true` so ambient roleplay never routes to it; Character NPCs default `false`. The Butler additionally responds to voice-address only from the GM, while Character NPCs are addressable by any participant.

**Amendment (2026-07-10, #280/#340): Butler GM-gate placement.** The Butler's GM-only voice-address rule ships as a detector-level drop (`orchestrator.WithButlerGMGate`): the route is discarded after `TargetMatch` returns, per the 2026-07-07 decision. This is correct while the Butler is absent from the live Matcher/Cast, but it violates this ADR's #225 semantics the day the Butler joins the roster (Epic 7, #256): a butler hit from a non-GM speaker still consumes a `MaxTargets` slot (shadowing a co-named NPC into routing nowhere) and is still recorded as lastAddressed (black-holing the next unnamed continuation). Before #256 lands, the gate must move matcher-side as a pre-cap eligibility drop — excluded from the published set, the cap, and lastAddressed, like a muted agent but without the sole-addressee publish — which requires the speaker's id in the scoring call. Tracked as a blocker on #256.

**Resolved (2026-07-10, #299).** The gate moved matcher-side: `Config.ButlerGMGate` + `Matcher.TargetMatchFrom(speakerID, text)` drop every Butler-role candidate from the scored set **before** scoring, the `MaxTargets` cap, and `lastAddressed` whenever the speaker fails the gate (an empty SpeakerID fails closed). The orchestrator detector prefers a `SpeakerAwareMatcher` (passing `STTFinal.SpeakerID`); the former detector-level `WithButlerGMGate` drop is retained belt-and-braces for non-SpeakerID-aware matchers. The matcher still scores **text only** — the SpeakerID is used solely as the pre-cap Butler-eligibility filter, never as a score input. A nil gate leaves the Butler addressable by any speaker (the #299 rollout default; since ADR-0055 only the no-DB `-hardcoded` smoke path and the bench remain nil — web/all AND standalone voice mode arm it from the GM-identity checker: tenant-bound operator ∪ env allowlist).

**Fuzzy name matching.** STT mishears proper nouns, so matching is fuzzy yet deterministic. A per-language phonetic encoder is chosen from a registry — `de` → Kölner Phonetik (`gopkg.in/Regis24GmbH/go-phonetics.v3`), `en` → Double Metaphone (`github.com/antzucaro/matchr`); further languages register their own encoder. Matching joins sliding windows of 1..N adjacent tokens before encoding (so "grim jaw" ≈ "Grimjaw"), and a rune-length floor keeps short tokens exact-only to avoid article/filler collisions. Behind phonetics sits a universal **edit-distance net** (`matchr.DamerauLevenshtein`, bounded by a max-distance knob), tried on a phonetic miss; for a language with no registered phonetic encoder, edit-distance is the entire fuzzy layer. This requires a `language` field on Campaign.

**Derived truncation aliases.** STT sometimes clips a name's leading consonant, yielding a fragment below the rune floor that then matches nothing ("Bart" heard as "Art", #197). Each Agent therefore carries auto-derived truncation aliases — the name/aliases minus their leading consonant — matched **exact-only and only when the matched window opens the utterance**, so a mid-sentence noun ("was für eine Art…") never routes. A derived hit scores just below an exact name (0.99) and above the phonetic tier (0.9), leaving the tier order **exact 1.0 > derived-exact 0.99 > phonetic 0.9 > edit ≤ 0.89**; it never reaches the phonetic or edit tiers, and the rune floor, phonetic tier, and edit net for real names and configured aliases stay byte-identical. Vowel-initial names derive nothing, and configured aliases keep position-free fuzzy matching.

**Pure function over a swappable index.** Each `TargetMatch` call is a pure function over the fuzzy name index — no vendor and no LLM in the loop — so the whole chain is unit-testable (ADR-0019, ADR-0021). The roster is **dynamic**, not fixed at construction: `Matcher.Add` and `Matcher.Remove` bring a Character NPC into or out of the scene mid-Voice Session. They rebuild the fuzzy index and the roster together under the matcher's mutex, and `TargetMatch` scores the index **under that same mutex**, so one scoring pass always sees a mutually consistent index/roster pair — never one rebuild's index against another's roster. (An earlier revision read the index lock-free via an `atomic.Pointer`; that let a `Remove` landing between the index read and the roster read shift survivor indices and misattribute name scores — #145.) Each scoring call remains pure against the index/roster snapshot it captured. (`Remove` also prunes the departed Agent's last-addressed and interruption state so a later unnamed continuation cannot resurrect it.)

**Muted Agents stay routable, name-gated (#225).** A GM can mute an Agent mid-Session (#211). Mute is **matcher-internal routing state**: `Matcher.SetMuted` sets it under the same mutex as the index and roster, so a scoring pass reads a consistent index/roster/mute triple and mute **never rebuilds the index** (the one-snapshot invariant above, #145). A muted Agent **stays in the fuzzy index and is still matched by name/alias**. An earlier revision instead *dropped* the muted Agent from the matcher; that stopped its name matching, so an explicit address ("Bart, hörst du mich?") fell through to the ambient heuristics and re-routed to a **different** NPC — the #225 failure. Instead a muted Agent is name-gated exactly like an Address-Only one: excluded from every ambient heuristic (continuation, interruption, single-NPC fallback), dropped from the published set whenever an unmuted Agent is also addressed (so a muted name never wins a tie-break or consumes a `MaxTargets` slot), and never recorded as last-addressed (so it cannot black-hole the next unnamed follow-up). It is published **only when it is the sole addressee** — an explicit solo address to a muted NPC — so the decision reaches the turn-taking layer's mute gate, which ends the turn before any audio or transcript line (ADR-0012, ADR-0027), rather than re-routing. Muting prunes the Agent's last-addressed and interruption state on the unmuted→muted transition (mirroring `Remove`); unmuting restores full addressability at once, and `Remove` clears the flag so a re-added Agent starts unmuted.

**Amendment (2026-07-12, #400/#413): the Vocative Flag tie-break.** `NameMatch` contributes a **flat** weight, so every name-matched Agent totals the same score — an exactly-heard name (1.0) and an incidental phonetic collision (0.9) are indistinguishable by total. When one utterance names two Agents this tie must be broken, and the live misroutes showed raw similarity alone is wrong: "So, Glyfoxa, was hat Bart über sein Gasthaus erzählt?" addresses the Butler (a ph→f phonetic hit, 0.9) but *mentions* the Character Bart (exact, 1.0) as the topic, and a similarity-first tie-break handed the turn to Bart (#400); symmetrically a Butler with a common-word name ("Gott") stole asks plainly addressed to a Character whenever a phonetically-colliding topic word ("geht"/"gute" ≡ "Gott" under Kölner Phonetik) appeared (#413).

The signal that separates *addressee* from *topic* is punctuation: a spoken vocative is bracketed off ("**Glyfoxa,** …", "…, **Gesa?**"), whereas a topic mention sits mid-clause ("was hat **Bart** …"). A matched span covering utterance tokens `[s..e]` is **Vocative-flagged** iff it is **left-marked** (`s` opens the utterance *or* the gap before it holds a marker rune), **right-marked** (`e` ends the utterance *or* the gap after it holds one), **and no marker rune sits inside the span** — the two-sided rule, so "frag **Bart,**" (comma-*followed* but word-preceded) does not flag. The marker set is `, . ! ? ; : … – —`; the **ASCII hyphen is excluded** so a hyphenated name stays one flaggable span. The flag is computed per Agent over **only its best-similarity spans** (so a low-tier collision word never lends its flag to an exact hit) and affects **ranking only** — never eligibility, `AnyNameMatched`, the AddressOnly/muted gates, or the pre-scoring GM-gate drop.

The tie-break chain is therefore: **(1) total desc → (2) Vocative-flagged before unflagged → (3) name-similarity desc → (4) earliest matched position asc → (5) stable roster order.** This routes the #400/#413 lines correctly (the flagged direct address wins even at a lower similarity tier) while leaving char-vs-char ties (#198 "gerade"≈"Greta", #199 derived-alias) to resolve on tiers 3–4 exactly as before. Two **accepted residuals** remain, mitigated at configuration time by the Butler rename-collision warning (#414) rather than at match time: an utterance with **no punctuation at all** produces zero flags, so tier 2 is a wash and tier 3 restores plain score order ("So Glyfoxa was hat Bart …" → Bart); and a **fronted, comma'd collision word** with no competing addressee ("Gerade, als ich ankam …" flags the "Greta" family; a sole "Oh Gott," exclamation flags the Butler) still routes to the collided Agent, because deterministic matching cannot tell an exclamation from an address of the same token. Tokenization on the utterance path is **offset-preserving** — token text byte-identical to the name-path tokenizer (pinned by a property test), carrying byte ranges only so the inter-token gaps can be read for markers.

**Why deterministic, not an LLM judge.** Address Detection is in the hot path before the Agent's own LLM call (Hot Context targets <50ms). An LLM judge would add 200–1000ms and drag cassette nondeterminism into the most-tested orchestrator component. Deterministic matching is sub-millisecond.

**Amendment (2026-07-27, live beta): the ambient stages get a clock, a floor, and an off-switch.** Live testing of the public-beta stack found NPCs answering far more often than anyone addressed them, to the point where players talking to each other kept waking them. The chain as specified above is the cause: stages 2 and 3 were each written as *decisive* — either one alone addresses an Agent — and neither carries a time bound or a substance floor, which makes stage 4 ("no target") effectively unreachable in an ordinary campaign. Three changes, all inside the matcher seam:

1. **Last-speaker continuation expires.** `lastAddressed` is stamped with the decision time and `LastAddressed` carries a `Within` bound (`Config.ContinuationWindow`, default **30s**, sized to cover an Agent's own spoken answer plus the human's reply pause). Before this the claim was permanent: an Agent named once at the start of a session scored the full decisive weight on EVERY unnamed utterance from EVERY speaker for the rest of it — hours later, after arbitrary silence, from a speaker who had never addressed it. The window is the one live-tunable knob on address scoring (`GLYPHOXA_ADDRESS_CONTINUATION_WINDOW`); a negative `ContinuationWindow` restores the unbounded behaviour.

2. **The single-NPC fallback corroborates instead of deciding.** `SoleActiveNPC` drops from weight 1.0 to **0.5** against the unchanged 1.0 threshold, so it can reinforce another signal (expertise, continuation) but no longer addresses on its own. In the beta topology — the Address-Only Butler plus exactly one Character NPC — the decisive weight meant that NPC answered 100% of non-empty finals: side conversations, thinking aloud, a cough that transcribed to a word. A lone NPC is now opened by name like any other, after which continuation carries the exchange.

3. **A substance gate drops pure backchannel.** An utterance whose every token is a filler VOCALIZATION ("mhm", "hm", "äh", "aha") — or a known filler phrase ("ach so") — and that names nobody routes NOWHERE. It is applied inside `match`, after the recency word buffer is fed and before any heuristic scores, so the words still inform later turns; transcription, the Transcript, and the bus event are untouched — the same contract the detector's empty-final guard honours. A dropped backchannel refreshes the continuation *timestamp* without changing who holds it, because an "mhm" acknowledges the exchange it interrupts and must not let it age out.

   The vocabulary holds **only** vocalizations. Lexical affirmatives and negatives ("ja", "nein", "okay", "genau", "yes", "no", "sure") are deliberately excluded even though they are the most frequent backchannel tokens in a real recording: they are also the most frequent shape of a genuine reply, since a Character NPC asks "Willst du den Schlüssel?" and the entire answer is "Ja." The matcher holds no state about whether the addressed Agent just asked a question, so it cannot tell the two apart — and when it cannot tell, the safe failure is an extra NPC line, not dead air after a direct answer. (An earlier revision of this amendment did include them, and review caught it: with a live continuation claim, "Ja."/"Nein."/"Yes." routed nowhere.) Each language consults only its own list, falling back to English only when it has none — cross-consulting made a German session drop "Er." and "Um.". Naming an Agent bypasses the gate entirely, so "Bart!" still routes.

**Interruption revokes continuation, it does not reward it.** `Matcher.ClearContinuation(agentID)` drops one Agent from the last-addressed set; the orchestrator's `AddressDetector` calls it on a `BargeDetected` naming that Agent (`InterruptibleMatcher`, ADR-0027 amendment). This closes the loop that made the symptom feel barge-specific: the interrupting speech is itself a routable final a moment later, and permanent continuation pulled it straight back onto the Agent the human had just cut off, so an interruption produced a NEW turn instead of ending one. Note the sign — the pre-existing `RecentlyInterrupted` heuristic *rewards* the interrupted Agent and stays out of the default stack (#442); the wanted behaviour is the opposite.

**The scoring stack is wiring-configurable.** `rosterDeps.heuristics` threads a stack from the wiring layer into `address.Config.Heuristics`, so weights and windows are a deployment concern rather than a code change and a release. Production passes `DefaultHeuristicsWithin(continuationWindow())`.

**Amendment (2026-11-20, audit sweep): a fuzzy name needs vocative evidence, continuation belongs to its speaker and is anchored to the reply, and the unfed heuristics are gone.** The 2026-07-27 amendment bounded the *ambient* stages; the "NPCs answer far too often" complaint survived it, because stage 1 itself was the leak. Three changes, measured on a corpus (`pkg/voice/address/corpus_test.go`: a roster of short common-sounding names — Bart, Greta, Mira, Flo, Tom, Anna, Rolf — against 76 German and 51 English everyday table-talk utterances and 56 genuine addresses including STT mishearings). Before: 59 of 127 unaddressed utterances routed to an NPC (precision 0.49, recall 1.00). After: 0 of 127 (precision 1.00, recall 1.00), with the residue and the deliberate misses pinned in the same file.

1. **A non-exact name hit is an address only with vocative evidence.** The fuzzy tiers were *decisive on their own*: any token anywhere in an utterance that shared a phonetic code with a name, or sat within two edits of it, addressed that Agent. A phonetic code drops the vowels and collapses the consonants, so a short name shares it with a slice of everyday vocabulary — "Seid ihr bereit?", "Gib mir das Brot." → Bart; "Das Meer ist ruhig." → Mira; "Zeig mir mal die Karte." → Greta; English "more", "part of", "great", "start". Now an **exact** name (or alias) still addresses in any position, punctuated or not — but a phonetic hit, an edit-distance hit, or a derived truncation alias (#197) counts **only when its span carries the Vocative Flag** (bracketed as a direct address: "Bard, …", "…, Barth?", "Also, Barth, …") **and is not a single everyday word of the Campaign Language** ("Great, let's go." is not "Greta, let's go."; `commonwords.go`, a frequency list per language — an exact match is never filtered, so an NPC really named "Wolf" is unaffected). The Vocative Flag was a tie-break; for non-exact hits it is now a precondition. The rule lives in `fuzzyIndex.score`'s address mode; the Appearances index (`NameIndex`), which asks "was this named" and has no punctuation to read, keeps the unconditional mode.

   Two floors moved with it. The **edit-distance net** allows one edit below seven runes and two from seven (`NameMatchConfig.LongNameRunes`): two edits rewrite half of a four-letter name. The **phonetic tier stays unbounded by edit distance** — the audit proposed capping it at two edits, and that was tried and rejected: the cross-orthography renderings the tier exists for ("Yeager" for "Jäger", "nite" for "Knight", #199) sit three and four edits out, *farther* than the collisions ("Brot"/"Bart" is two), so distance cannot separate them. Position and the everyday-word list do.

   Accepted costs, each pinned: an STT that emits **no punctuation** now routes exact names only ("bard what is the special" reaches nobody; "bart was hast du" still does). A misheard name that *is* an everyday word needs the name repeated. "So, woran erinnerst du dich?" where "Flo," was heard as "So," **does not route**: a three-rune name is exact-only by the rune floor, and "So," opens a large share of all sentences in both languages — inside a live exchange the speaker's continuation carries it, cold it needs the name. Still routing, by nature: a vocative to somebody else whose name is a near-homophone of an NPC's ("Hanna, kommst du?" with an NPC Anna), and an exact name used as a topic or as the noun it also is ("Der Bart muss ab.").

2. **The continuation claim is speaker-scoped.** The claim opened by a named address belongs to the speaker who made it: only that speaker continues without a name, and only that speaker's Backchannel refreshes the anchor. Previously any speaker's unnamed utterance inside the window was answered by the NPC *and re-stamped the window*, so one address kept an NPC answering side talk for as long as the table kept talking. The scope applies when both the opener and the current speaker are attributed (Speaker Lanes, ADR-0050); an unattributed utterance or opener falls back to the table-wide claim, so nothing changes for a deployment without speaker identity. A named address by anyone moves the claim to that speaker. The cost is real and accepted: a *second* player's unnamed follow-up to an NPC another player addressed now needs the name.

3. **The Continuation Window is anchored to the reply, not to the address.** The 30s were sized "to cover the Agent's own spoken answer plus the human's reply pause", but counted from the routing decision — so a 24-second answer left six seconds and a longer one left none (observed live: the follow-up to a long answer was ignored). The `AddressDetector` now remembers which Agents it routed each recent turn to and, on every `FirstAudio` of such a turn, calls `Matcher.ExtendContinuation` (`ReplyAwareMatcher`), which moves the anchor **only if that Agent still holds the claim** — a turn that was superseded, barged (`ClearContinuation`), muted or removed re-arms nothing. `FirstAudio` fires per sentence as it reaches the playback pump, so the anchor trails the true end of the reply by at most the last sentence; a terminal "turn completed" event is the exact signal and should feed the same call once it exists. **It exists now (same day):** every clean turn ends with `TurnEnded{completed}` (ADR-0040), and the detector calls `ExtendContinuation` for the turn's Agent on it as well, so the window is measured from the moment the reply finished playing. The `FirstAudio` refresh stays — it is what keeps the claim alive *during* an answer longer than the window. Only `completed` extends: a failed, muted, superseded or text-delivered turn leaves the anchor where its audio (if any) put it, and a barge revokes the claim.

**Note (2026-11-20): `MaxTargets > 1` no longer leads to an Ensemble Turn.** The unshipped Ensemble implementation was removed (ADR-0025). The matcher's multi-target scoring is kept — it is general Address Detection, cheap, and tested — but the `AddressDetector` publishes only the first decision that survives its gates. Where the text above says the Ensemble Turn "is reachable through this knob", only the decision set is.

**Trim.** `ExpertOnRecentWord` (nothing ever set `Agent.Expertise`), `RecentlyInterrupted` with `Matcher.NoteInterruption` (never wired; the Barge-in signal is `ClearContinuation`, with the opposite sign), the recent-word buffer and interruption map they read — rebuilt under the matcher lock on every utterance — and the test-only `WholeWordMatcher` are removed. `SoleActiveNPC` leaves the default stack: at 0.5 it could only ever corroborate the removed expertise hint, so it could not reach the threshold with anything; it remains as an opt-in heuristic. The shipped stack is `NameMatch` + `LastAddressed`. Where the text above mentions the recency buffer, interruption state or `RecentlyInterrupted`, this paragraph supersedes it.

**Considered options:**

- **LLM judge on every utterance** — rejected for v1.0 (latency + nondeterminism); kept reachable behind the interface.
- **Two-stage (heuristic + LLM fallback)** — deferred; reintroduces nondeterminism on the least-predictable path.
- **Exact match only (v1-style)** — rejected; STT name mishearings fall through silently.
- **STT keyterm hints instead of fuzzy matching** — viable, deferred; fuzzy matching chosen so robustness does not depend on per-provider hint support. (Added *beside* the fuzzy chain on 2026-11-22, see the amendment below.)

**Amendment (2026-11-22, #701): the recognizer is told the names; the matcher is unchanged.** Until now a name reached STT only as audio and reached this chain only as whatever text came back. The 2026-11-20 amendment accepted that a misheard three-rune name is not heard ("So, woran erinnerst du dich?" for "Flo, …"); live tests showed the cost was higher than expected, because short names are exactly the ones a general recognizer gets wrong. Each Voice Session now sends its Cast, Butler and player-character names and aliases to the STT provider as keyterms (ADR-0042, keyterm amendment 2026-11-22, which holds the measurements). Nothing in this chain moved: the rune floor still keeps names under four runes exact-only, the tier order and the vocative rule are as above, and the fuzzy tiers remain the only recovery for a provider without hint support. Two consequences belong here. First, the "exact name used as the noun it also is" residue grows from the name's spelling to its homophones — with an NPC called Flo, a spoken "Floh" or "Flow" is now transcribed "Flo" and routes. Second, to bound that, a name that is an everyday word of the Campaign Language is not sent as a keyterm; the test is this package's own everyday-word list, exported as `address.IsCommonWord` so there is one vocabulary, not two. A vocative-position rule for short names would remove the residue at the matcher and is the open follow-up.
